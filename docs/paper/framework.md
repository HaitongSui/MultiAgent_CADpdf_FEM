## 1. 摘要（结构化草稿）

- **背景**：既有桥梁的评估和数字孪生都需要有限元模型。大量桥梁只有扫描图纸，人工建模成本高；视觉语言模型（VLM）单次读图会出错，而且无法察觉自己的错误。
- **方法**：提出一个多智能体工作流，包括 Curriculum、Actor、Verifier、Memory 四个 Agent。
  - Verifier 不看 Actor 的推理，只依据独立的工程证据判断：跨图一致性、算术与物理不变量、同类构件一致性、隔离上下文中的独立复读。
  - 只有通过验证的结论和经验才写入记忆。校核规则升级时，记忆会被回溯审计；人工反馈记录来源；冻结后的记忆在测试时复用，用来生成 FEM 模型。
- **实验**：在 `[n_b]` 座桥、`[n_s]` 张扫描图纸上评估，开发集和测试集分离，真值由工程师独立标注。
- **结果**：与单次读图相比，字段级错误率从 `[x]%` 降到 `[y]%`；截面性质误差 `[z]%`；每座桥成本 `[$]`，人工干预 `[k]` 次。读图误差对结构响应的影响由敏感性分析量化。
- **意义**：工程不变量可以充当 LLM Agent 自我改进的可靠反馈信号，校核覆盖率决定剩余的工程风险。

- **C1** 验证驱动的多智能体读图框架：Actor 与 Verifier 上下文隔离，黑板加数据驱动调度，预算受控。
- **C2** 工程约束校核分类法和**校核覆盖率**指标，用来衡量哪些读出字段有独立证据支撑。

- **C5** 开源代码、提示词、校核和记忆文件；数据在许可允许的范围内公开。

## 3. 引言（Introduction）

1. **工程需求**：既有桥梁的评估、加固和数字孪生都需要可计算的模型，而图纸多为扫描件。
2. **现有方法的不足**：
   - OCR 和规则解析适应不了自由版式的工程图；
   - VLM 单次读图有幻觉和口径错误，而且没有可靠的自检手段；
   - 现有的自我改进 Agent 大多依赖可以执行的反馈（如代码测试），工程读图缺少这样的反馈信号。
3. **研究空白**：用什么作为读图结果的可靠反馈？怎样防止错误的经验在记忆中扩散？
4. **本文思路**：把工程不变量用作验证信号，把验证作为写入记忆的门槛。
5. RQ1–RQ4、贡献 C1–C5、全文结构。

## 5. 方法（Methodology）

### 5.1 问题定义（形式化）

- 图纸集 \(D=\{d_1,\dots,d_n\}\)；目标字段集合 \(F\)，包括截面板件、吊索规格、几何尺寸等。
- 读图任务 \(t\) 输出结论 \(c_t: F_t \to V\)。
- 校核函数 \(v_j(c_t, M, R) \to \{0,1\}\)，依据是记忆 \(M\) 和已有的读图结果 \(R\)。
- 写入规则：只有当 \(\bigwedge_j v_j = 1\) 时，才执行 \(M \leftarrow M \cup \{c_t, \ell_t\}\)，其中 \(\ell_t\) 是该次得到的经验。
- **校核覆盖率**：\(\mathrm{Cov} = |\{f \in F : \exists v_j \text{ 依赖 } f\}| / |F|\)。另外按工程重要性加权，得到 \(\mathrm{Cov}_w\)，权重取自 §6.4 的敏感性分析。

### 5.2 框架总览（Fig. 1）

- 黑板、Agent 的 requires/optional/provides 声明、数据驱动调度、REQUEST 反馈回路。
- 三个阶段：广度（图纸目录）→ 深度（截面、吊索）→ 复用（冻结记忆后生成 FEM）。

### 5.3 Curriculum

- 根据缺口、依赖关系、尝试次数和预算挑选任务；用读出的图纸目录定位页码。
- 失败的校核项作为提示带入下一次尝试。
- 当前的局限：任务清单是人工定义的。未来工作是从模型的"假定值清单"自动生成缺口。

### 5.4 Actor

- 页面切分：概览加 4 张原分辨率分块，长边受 API 限制。
- 提示词由三部分组成：任务目标、记忆中已验证的经验、输出格式。全文提示词放在附录。
- 每次调用都在新的独立上下文中进行。

### 5.5 Verifier（Table 2：校核分类）

| 类别 | 定义 | 例子 |
|---|---|---|
| V1 跨图 | 同一个量在不同图纸上必须相等 | 腹板间距 = 一般图上的主梁宽；拱肋段长 = 基本尺寸图上的部材长链 |
| V2 算术与物理 | 由定义或物理关系导出的等式 | 吊索面积 = 丝数 × 38.48 mm²；梁高 = 翼缘 + 腹板 + 翼缘；肋数 = 腹板高 / 间距 − 1 |
| V3 对称与一致 | 结构对称；同类构件的布置相同（与记忆中其他已验证构件比较） | 吊索左右对称；同高度拱肋段的加劲肋布置相同 |
| V4 结构完整性 | 每种板件只报一条；必需字段齐全 | 不得按每块板重复列出 |
| V5 独立复读 | 隔离上下文中逐条复读，只比较数值和钢种 | — |

- 讨论 V3 的局限：**一致性不等于正确性**。两处犯同样的错误时，V3 拦不住，需要 V2 或人工审核兜底（§6.5 有实例）。

### 5.6 记忆（Memory）

- 存储格式：`knowledge.json`、`lessons.md`、`episodes/`，都是纯文本，可以用 git 审阅。
- 写入：通过验证才提交。
- **回溯审计**：每次启动时，用当前的校核重新检查记忆中的全部结论；所有结论以同一份快照为准；矛盾的结论双双逐出，同时撤回只由它们产生的经验。
- **人工反馈**：审核人可以把某项打回，说明原因但不给答案。
- **改进来源标注**：每个 episode 记录这次改进来自哪里，用于 §6.5 的归因分析：
  - `system`：重试、经验积累、审计；
  - `reviewer`：审核人打回；
  - `developer`：开发者修改了校核规则。
- 冻结：测试时复用，记忆只读。

### 5.7 从记忆生成 FEM

- 板件组装成钢箱或 I 形截面（扭转常数用 Bredt 公式）；截面按构件分段映射。
- 拱桥模型：主梁兼作系杆、拱肋、V 形吊索、横梁；边界条件与荷载（恒载、B 活载）。
- 推定值的处理：图纸集里缺少的构件（如主梁中段）用相邻图纸的数据推定，并在报告中单独标注。

## 6. 实验（Experiments）

### 6.0 实验设置

**数据（Table 3）**

| 集合 | 内容 | 用途 |
|---|---|---|
| 开发集 | 桥 A（新田豊島橋）的部分图纸 | 设计校核规则、调试提示词 |
| 测试集（同桥） | 桥 A 的其余细节图（第 1 段拱肋、端横梁、支座、横向联结……） | 在没见过的图纸上评估 |
| 测试集（跨桥） | 桥 B、C（不同桥型，**待收集**） | RQ3 迁移 |

- 校核规则在开发集上**冻结**之后，才能在测试集上运行。
- 公开桥名和图纸前需要取得许可，必要时匿名化。

**真值**

- 由两名工程师独立标注字段，报告 Cohen's κ 或逐字段一致率；不一致的地方由第三人裁定。
- 会话中由模型生成的转录**不作为真值**，只作为"离线回放"用的测试样本。

**基线**

| 编号 | 方法 |
|---|---|
| B0 | OCR 加规则解析（现有的 `cad2fem bridge` 路线），扫描件上预计不可用 |
| B1 | VLM 单次读图（相同的提示词和切分，不迭代、不用记忆） |
| B2 | VLM 多次采样取多数（self-consistency，k = `[5]`） |
| B3 | 人工建模：记录工程师从读图到建模所用的时间 |
| Ours | 完整系统 |

**指标（Table 4）**

| 指标 | 定义 |
|---|---|
| 字段准确率 | 读出值与真值完全一致的比例；数值字段允许 `[0.5]%` 的相对容差 |
| 截面性质误差 | A、Iyy、Izz、J 的相对误差 |
| 响应误差 | 用真值截面建立模型后，跨中挠度、拱肋轴力、吊索拉力的相对差 |
| 成本 | 金额、调用次数、墙钟时间 |
| 人工干预 | 审核人打回次数、开发者修改校核的次数 |
| 校核覆盖率 | 前述的 Cov 和 Cov_w |
| 误放行率 | 通过了验证、但与真值不符的结论所占的比例（最关键的安全指标） |

**协议**

- 每种配置重复 `[5]` 次，报告均值、标准差和 95% 置信区间；用配对检验比较。
- 记录模型版本、日期和温度设置；同一组实验内固定。

### 6.3 RQ3：迁移

- 用在开发集上积累的记忆（冻结后）读测试集，与空记忆对比。
- 跨桥实验：用桥 A 的记忆读桥 B，衡量经验迁移的正面和负面效果。

### 6.4 RQ4：敏感性分析与覆盖率

- 对每个读出字段施加 ±1 级扰动（例如板厚换成相邻规格、数量 ±1），重新计算模型，得到响应变化，即**字段重要性**。
- Fig. 3：字段重要性与校核覆盖率的散点图，找出"重要但未被覆盖"的字段。
- 据此给出校核设计的建议：重要性高的字段至少需要一条 V1 或 V2 校核。

### 6.5 失败模式与改进归因（定性）

用 Table 7 列出实际观察到的失败模式，每条都标注发现者和修正者（system、reviewer、developer）：

| # | 失败模式 | 后果 | 如何发现 | 修正来源 |
|---|---|---|---|---|
| F1 | 独立复读过严：图纸写法与结论的表述不同，就判为不一致 | 正确结论被拒（假阴性） | 运行日志 | developer：改为只比较数值和钢种 |
| F2 | 同一构件按每块板重复列出 | 拱肋第 5 段面积多算 11% | 开发者对照真值后发现 | developer 新增 V4 校核 → system 审计逐出 → system 重读 |
| F3 | 数量口径错误（把两块腹板合计的件数当作每块腹板的数量） | 拱肋第 4、5 段同样读错，V3 拦不住 | 开发者看原图确认 | developer 新增 V2（肋间距）→ reviewer 打回 → system 重读 |

- 讨论：在开发阶段，系统自主完成的改进（重试、审计、重读）都依赖开发者先加入新的校核。这正说明 **C2 覆盖率**的重要性，也引出未来工作：由 Agent 提出候选校核规则，再用已验证的记忆检验这些规则。

### 6.6 对结构分析的影响（端到端）

- 三个模型对比：全部假定值、系统读出的截面、真值截面。
- 与外部参照对比，至少选一项：设计计算书、竣工资料、独立的商用软件模型。
- 吊索拉力与设计张力的差异要专门解释：设计值包含预张和长度调整。可以在模型中加入吊索长度调整后再对比，否则在文中明确说明这一比较的局限。

## 7. 讨论（Discussion）

- 人的角色：审核人和开发者的工作量与 B3 人工建模相比是多少。
- 成本与收益：每座桥的金额和时间。
- 能否推广到其他桥型或其他国家的图纸：哪些校核可以通用（V2、V4），哪些依赖具体桥梁（V1 的部分规则）。
- 安全性：误放行率，以及在工程中应如何使用这套系统（辅助工具，需人工签核）。

### 效度威胁（Threats to Validity）

- **内部效度**：校核规则可能偏向开发集，用冻结规则、在测试集上评估来缓解；模型版本更新的影响。
- **外部效度**：桥型和图纸风格的代表性有限（目前是日本的钢拱桥）。
- **构念效度**：字段准确率能否代表工程上的可用性，用 §6.4 的响应误差来回应。
- **结论效度**：重复次数和统计检验。

回答 RQ1–RQ4，总结 C1–C5，指出局限和未来工作：自动发现缺口、Agent 提出候选校核、更多桥型。
